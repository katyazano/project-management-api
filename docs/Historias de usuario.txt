*Historia 1.1: Registro y Acceso*

Como usuario nuevo,
quiero poder registrarme de forma segura y obtener un token de acceso,
para poder crear y gestionar mis proyectos de manera privada.

Criterios de Aceptación:
-El sistema debe recibir las credenciales vía POST y validar el formato del correo con Pydantic.
-Las contraseñas no deben guardarse en texto plano (deben ser hasheadas, ej. con Bcrypt).
-Al autenticarse correctamente, el sistema debe devolver un token JWT válido.
-Si las credenciales son incorrectas, debe devolver un error 401 Unauthorized.


*Historia 2.1: Creación de Proyectos*

Como usuario autenticado,
quiero crear un nuevo proyecto en la plataforma,
para tener un espacio centralizado donde mi equipo pueda organizar el trabajo.

Criterios de Aceptación:
-Solo los usuarios con un token JWT válido pueden consumir el endpoint de creación.
-El usuario que crea el proyecto se asigna automáticamente como OWNER (Dueño) en la base de datos.
-El endpoint debe devolver el ID del proyecto recién creado con un código 201 Created.


*Historia 3.1: Invitación por Correo (AWS SES)*

Como dueño de un proyecto,
quiero generar un enlace de invitación seguro y enviarlo por correo electrónico,
para que otros colegas puedan unirse a mi proyecto.

Criterios de Aceptación:
-Solo el OWNER del proyecto puede disparar este endpoint.
-El sistema debe generar un token temporal que incluya el ID del proyecto y el correo del invitado.
-El sistema debe enviar un correo electrónico al invitado a través de Amazon SES con el enlace de acceso.

*Historia 3.2: Aceptación de Invitación*

Como usuario invitado,
quiero hacer clic en el enlace que recibí por correo,
para ser agregado automáticamente al proyecto como editor.

Criterios de Aceptación:
-El endpoint /join debe validar que el token de la URL no haya expirado.
-El sistema debe verificar que el correo del usuario logueado coincide exactamente con el correo al que se le emitió el token; de lo contrario, devuelve 403 Forbidden.
-Al unirse, el usuario recibe el rol de EDITOR en la base de datos.


*Historia 4.1: Subida de Documentos (AWS S3)*

Como miembro de un proyecto,
quiero subir archivos a la plataforma,
para compartir recursos y documentos con mi equipo.

Criterios de Aceptación:
-El archivo debe validarse y enviarse a un bucket de almacenamiento seguro (AWS S3).
-La base de datos debe guardar una referencia al documento (ej. la URL o la llave del bucket).
-El código debe implementar Lazy Initialization para que el entorno de CI/CD pueda simular la subida usando Moto sin generar costos reales.
